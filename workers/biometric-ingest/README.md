# Meqat Biometric Ingest Worker (v2 — استقبال عام متعدد المحوّلات)

يستقبل حركات الحضور من أجهزة وأنظمة مختلفة عبر **محوّلات (adapters)**، يطبّعها إلى حدث موحّد، يطابقها مع الموظف، ثم يكتبها في `employees/{id}/records/bio_{ms}` (نفس مسار الاستيراد، فلا تتكرر الحركة بين Push والاستيراد). الأجهزة تُعرَّف وتُربط وتُدار من لوحة ميقات (تبويب **أجهزة البصمة**).

## ما الذي يغطيه (وما لا يغطيه)
| الطريقة | يغطي | الحالة |
|---|---|---|
| `zkteco-adms` — ADMS / iClock Push | ZKTeco وعدد كبير من الأجهزة المتوافقة معه | منفّذ ومختبر على الوحدة؛ **يلزم التحقق على الموديل/الـFirmware الفعلي** |
| `generic` — إشعارات HTTP (JSON/XML/multipart/سطور) بتعيين حقول تضبطه أنت | أي جهاز أو برنامج يدفع أحداثاً عبر HTTP (Hikvision HTTP Listening، Dahua، Suprema BioStar، أنظمة سحابية، سكربتات…) | منفّذ؛ التعيين يُضبط لكل جهاز |
| `meqat-json-v1` | برنامج/وسيط يرسل JSON الموحّد | منفّذ |
| Local Connector (SDK/TCP داخل LAN، مثل سحب ZKTeco على المنفذ 4370) | أجهزة لا تصل الإنترنت أو لا تدعم Push | غير منفّذ بعد: يرسل إلى `/v1/hook` |
| استيراد الملفات (Excel/CSV/DAT) | أي جهاز يصدّر ملفاً | منفّذ في التطبيق ويبقى احتياطياً دائماً |

لا يوجد بروتوكول عالمي واحد؛ الجهاز الذي لا يدفع عبر HTTP ولا يصدّر ملفاً يحتاج Connector خاصاً به.

## المسارات
- `GET /health`
- `POST /v1/punch` — رأس `X-Meqat-Device: <id>` و`Authorization: Bearer <token>`
- `POST /v1/hook/<deviceId>/<token>` — للأجهزة/الأنظمة التي لا تستطيع ضبط رؤوس (الرمز داخل الرابط)
- `GET|POST /iclock/cdata?SN=…` و`/iclock/getrequest` و`/iclock/devicecmd` — ADMS؛ ويمكن إضافة `/t/<token>` قبلها إن سمح الجهاز بمسار
- كل الردود JSON ما عدا ADMS (نص `OK`)، وتفصّل حالة كل حركة: `stored` / `duplicate` / `pending`.

## المصادقة
- لكل جهاز رمز عشوائي طويل يُنشأ من اللوحة؛ يُخزَّن **SHA-256 فقط** في `biometricDevices` ويُعرض مرة واحدة، وتدويره/إلغاؤه فوري من اللوحة (لا حاجة لإعادة نشر Worker).
- أجهزة ADMS لا ترسل رأس تفويض، فتُعرَّف **بالرقم التسلسلي SN** المسجّل في اللوحة (جهاز غير مسجّل = 403). SN ليس سراً قوياً؛ إن سمح الجهاز بمسار فعّل «اشتراط رمز في المسار»، وإلا فالحماية الفعلية هي تسجيل SN مسبقاً وتعطيل الجهاز عند الشك.

## مطابقة الموظف
1. جدول `biometricMap` لكل (جهاز + معرّف) ⟵ موظف (تُوحَّد الأصفار البادئة والأرقام العربية).
2. إن لم يوجد ربط: `bioId` في ملف الموظف **بشرط أن يكون فريداً**. الملتبس أو غير المعروف يُحفظ في `biometricPending` ولا يضيع، ولا يُنشأ موظف تلقائياً.
3. أحداث بوقت مستقبلي (ساعة جهاز خاطئة) تُعلَّق ولا تُسجَّل.

## الوقت والحركة
- الوقت بلا منطقة زمنية يُفسَّر بإزاحة الجهاز `tzOffset` (ليبيا 120) وليس بتوقيت الخادم؛ والوقت ذو الإزاحة الصريحة يُؤخذ كما هو.
- حضور/انصراف: افتراضياً **بالتناوب داخل يوم الموظف** (أغلب الأجهزة لا تُميّز موثوقاً)، أو من حالة الجهاز إن اخترت ذلك للجهاز.

## التكرار
معرّف السجل `bio_{ms}` يُنشأ بشرط «غير موجود»: إعادة الإرسال أو الترتيب المعكوس أو الاستيراد اللاحق لنفس الحركة لا يكرّر ولا يستبدل. حدثان للموظف نفسه في المللي ثانية نفسها يُعدّان حدثاً واحداً.

## الحصص المجانية
كل طلب يستعمل استدعاءات مجمّعة (batchGet / batchWrite) فيبقى تحت حد 50 استدعاءً خارجياً في الخطة المجانية (يتحقق منه اختبار دفعة 480 حركة). ADMS يستعلم كل 60 ثانية (`Delay=60`)؛ لا تخفّض هذه القيمة بلا داعٍ فالحد اليومي 100 ألف طلب لكل الأجهزة معاً.

## النشر
```sh
cd workers/biometric-ingest
npx wrangler secret put FIREBASE_CLIENT_EMAIL
npx wrangler secret put FIREBASE_PRIVATE_KEY
npx wrangler deploy
```
حساب الخدمة مخصّص بأقل صلاحية على Firestore (`roles/datastore.user`)، وليس مالك المشروع. بعد النشر: انشر `firestore.rules` الجديدة، ثم أضف الجهاز من اللوحة.
- أجهزة ZKTeco القديمة لا تدعم TLS: تحتاج نطاقاً مخصصاً يسمح بـ HTTP (لا تفعّل «Always Use HTTPS» على ذلك النطاق) لأن الجهاز لا يتبع التحويل. `workers.dev` HTTPS فقط.
- أول تشغيل: افحص Worker بـ `wrangler tail`، وسجّل حركة تجريبية، وطابق الوقت يدوياً قبل الاعتماد على الرواتب.
